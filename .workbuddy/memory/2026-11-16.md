## 实现主导航标签页分页功能

**需求**：用户反复要求"页面帮我做个分页处理把不然手机端一直往下滑,电脑也是嘞"

**实现方案**：
1. **HTML 结构**（已在上次完成）：在 `index.html` 中添加主导航标签页（总览、持仓、分析、更多），并为所有 section 添加 `data-page` 属性
2. **CSS 样式**：在 `style.css` 末尾添加 `.main-tabs` 和 `.main-tab` 样式，实现 sticky 定位和激活状态切换
3. **JavaScript 逻辑**：在 `app.js` 中添加 `initTabNavigation()` 函数处理标签页切换

**关键代码**：
- CSS: `.main-tabs` 使用 `position: sticky; top: 0` 保持导航栏固定
- CSS: `section[data-page]` 默认隐藏，`section[data-page].active` 显示
- JS: 点击标签页时切换 active class，并平滑滚动到顶部

**测试**：服务器启动正常（http://localhost:3456），前端页面已打开供用户验证

**技术细节**：
- 移动端优化：标签页使用 flex 布局，图标 + 文字垂直排列
- 响应式：小屏幕下调整图标和文字大小
- 交互：hover 效果、激活状态下底部蓝色边框
- 用户体验：切换标签页时平滑滚动到顶部

## 添加用户登录和数据隔离功能（v1.8）

**背景**：用户反馈两人共用一个账号，数据会混在一起累加，无法区分彼此的持仓。

**需求**：
- 创建两个固定账号：pxj（密码 pxj123）、sgw（密码 sgw123）
- 不开放注册，只有这两个账号可登录
- 每个账号的持仓数据完全隔离，互不干扰

**实现方案**：

1. **后端认证系统**：
   - 安装依赖：`jsonwebtoken`、`bcryptjs`
   - 新增 `users` 表存储账号和加密密码
   - 新增 `/api/auth/login` 接口验证账号密码，返回 JWT token（有效期 7 天）
   - 新增鉴权中间件 `backend/http/middleware/auth.js` 验证 token
   - 登录接口不需要 token，其他接口全部需要

2. **数据隔离**：
   - `holdings` 表新增 `user_id` 字段关联用户
   - 修改 `portfolioService.buildPortfolio()` 支持按 userId 过滤
   - 修改所有持仓相关路由（holdings、dashboard、portfolio）添加鉴权并传入 userId
   - 所有增删改查操作都加上 `WHERE user_id = ?` 条件

3. **前端登录页面**：
   - 新建 `frontend/login.html` 登录页面（渐变背景、现代设计）
   - 主页面 `index.html` 添加登录校验脚本：未登录自动跳转到登录页
   - 修改 `js/api.js`：所有请求自动携带 `Authorization: Bearer <token>`，401 自动跳转登录页
   - 主页面右上角显示当前用户名和退出按钮

4. **初始化脚本**：
   - `backend/scripts/init-users.js`：创建 users 表、添加 user_id 字段、插入两个账号
   - 本地已执行初始化，Render 部署后需在 Shell 中手动执行一次

**关键文件**：
- 后端：auth.js、auth middleware、init-users.js、holdings/dashboard/portfolio 路由、portfolioService
- 前端：login.html、index.html、api.js、app.js
- 文档：DEPLOY-LOGIN.md

**技术细节**：
- JWT Secret：`fund-assistant-secret-key-2026`（硬编码，生产环境建议改为环境变量）
- Token 有效期：7 天
- 密码加密：bcrypt（10 轮）

**部署步骤**（Render）：

2. 部署成功后在 Render Shell 执行：`node backend/scripts/init-users.js`
3. 访问 https://fund-assistant.onrender.com/login.html
